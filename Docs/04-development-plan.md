# 개발 계획 및 완료 기준

일정은 2026-11-15 제출 목표의 제안이며 완료 보장이 아니다.

## 단계
1. 11/12: 대상·핵심 흐름 합의, SDK 환경·수신 시험, 화면 골격.
2. 11/13: 다국어 화면, 차종 안내, 장소 2~3개 선택·정렬.
3. 11/14: 검증된 차량 상태·내비 연결, 실패 처리, 영상·기획서.
4. 11/15: 회귀 확인·제출물 정리. 새 기능 추가하지 않음.

## 기능 완료의 정의
- 빌드 성공과 실행 성공을 각각 기록.
- 실제 연동 기능은 실제 입력→응답→화면 증거가 있어야 완료.
- 모의 데이터와 실제 데이터가 표시상 구별됨.
- 언어 전환·재진입·연속 클릭·연결 끊김이 잘못된 성공 상태를 만들지 않음.
- 주행 제한에 맞는 UI 상태 검증.
- 관광 정보·차량 안내에 근거와 갱신 범위 명시.
- 개인정보·비밀키·SDK 바이너리 미포함.
- 공식 제출 양식 및 최신 공고와 대조.

## 제품 검증 계획
기존 매뉴얼/관광 목록/내비 흐름과 비교해 안내 찾기, 목적지 전달, 상태 이해 과제를 수행한다.
완료 시간, 잘못 이해한 항목, 도움 요청 횟수를 기록한다.
테스트 전에는 성능 수치·문의 감소·사용자 선호를 주장하지 않는다.
소규모 편의 표본 결과를 전체 외국인에게 일반화하지 않는다.

## 열린 결정
- 주기능을 관광 동선과 차량 안내 중 어디에 둘지.
- 초기 사용자·차종·언어.
- QR의 역할: 정적 링크인지 인증된 연결인지.
- AI를 1차 시제품에 포함할지.
- 사용할 관광 데이터와 콘텐츠 이용권.
- SDK 실제 수신에 따른 MVP 축소 범위.

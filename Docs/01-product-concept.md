# 기획 초안: 다국어 차량·여행 동행 가이드

상태: 논의용 초안 / 작성일: 2026-11-12 / 제품명·최종 타깃·범위 미확정

## 한 문장
처음 이용하는 차량의 안내와 여행자가 정리한 방문 목록을 연결해, 사용자의 언어로 차량을 이해하고 원하는 장소까지 이동하도록 돕는 Pleos 앱을 구상한다.

## 대상과 확장 가설
- 초기 사례: 한국을 방문해 Pleos 지원 차량을 빌린 외국인 관광객.
- 제주 사례는 대상이 구체적이라는 장점이 있으나, 실제 Pleos 탑재 렌터카 수와 배포 가능성은 미확인.
- 해외 출고 고객·공유차·해외 여행자로의 확대는 후속 검증 대상.
- OEM 출고 사전 설치는 정책상 존재하는 경로지만 별도 계약·차량 검증이 필요하며 수상 시 보장되지 않는다.

## 문제 가설
1. 처음 탄 차의 조작·현재 상태를 익숙한 언어로 이해하기 어렵다.
2. 휴대폰에 모아둔 관광 목록을 차량의 목적지·경유지로 옮기는 과정이 번거롭다.
3. 일반 관광 추천은 실제 이동과 차량 이용 단계에서 필요한 안내와 분리되어 있다.

위 문제의 빈도와 개선 효과, 앱 이용 의향은 아직 사용자 조사로 검증하지 않았다.

## 사용자 발상과 구현 범위 구분
| 발상 | 기획 방향 | 검증·범위 |
|---|---|---|
| QR로 바로 연결 | 차량/업체별 안내 링크에서 시작 | 정적 링크와 인증된 폰-차량 페어링은 다르다. 자동 페어링 미검증 |
| 차종별 정보·안내 | 차종을 지정한 검수 콘텐츠 제공 | 전 차종 자동 식별은 제외, 첫 시제품은 한 차종 |
| 차량 관련 AI 채팅 | 공식 매뉴얼 근거를 찾아 안내 | 자유 생성·고장 진단 제외. 콘텐츠 이용권·비용·외부 전송 확인 필요 |
| 관광 리스트 입력 | 원하는 장소 2~3개를 직접 선택·정렬 | 자동 최적 경로 계산과는 구분 |
| 주변 음식점·관광지 | 공개 관광 데이터와 출처·조회시각 표시 | 실시간 영업·예약·혼잡·최적성 보장 금지 |
| 차량 상태 | 실제 수신된 연료 또는 SOC, 문 상태 | SDK 선언 확인과 실제 수신 성공은 별개 |

## 첫 시연 장면(제안)
주차된 차량에서 언어를 고르고, 차종 안내를 확인한다. 여행자가 관광지 2~3개를 선택·정렬하고 목적지를 검토한 뒤 기본 차량 내비에 전달한다. 차량 상태 조회가 검증된 경우 상태에 맞는 안내 카드를 표시한다.

관광 추천·QR·AI·차량 가이드를 한 번에 완성하겠다고 약속하지 않는다. 핵심 흐름을 먼저 선택해야 한다.

## 기존 기능 대비 차별화 가설
현대차 Gleo의 매뉴얼 안내, 기존 내비의 경유지 기능, 기존 관광 추천과 각각 겹친다. “번역”, “AI 질문”, “최적 경로” 자체를 독점적 차별성으로 쓰지 않는다.
차별성은 **낯선 차량을 사용하는 여행자의 준비한 방문 목록과 차량 안내를 한 흐름으로 잇는 경험**에 있으며, 실제 편익은 비교 테스트 대상이다.

## 사업성 가설
- 사용자: 외국인 여행자 및 처음 차를 이용하는 운전자.
- 배포 후보: Pleos App Market, 렌터카·딜러 협업, 후속 OEM 사전 탑재 협의.
- 지표 후보: 대여 건당 사용률, 목적지 전달 완료율, 안내 과제 완료 시간, 문의 횟수.
- 제휴·매출·사용자 수·절감 효과가 확보된 상태가 아니다.

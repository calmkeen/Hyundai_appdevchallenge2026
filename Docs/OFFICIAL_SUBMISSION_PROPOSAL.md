# CarCue 공식 제출 기획서 원고

공식 참가신청서의 02 앱 프로젝트 소개 1~8 항목에 대응하는 편집 원고다. 제품명은 CarCue(카큐)다. 참가자 정보와 동의·서명은 이 원고에 포함하지 않는다. 원본 양식, 생성물, 렌더 QA는 Git에 포함하지 않는다.

<!-- slot:app_summary -->
CarCue(카큐)는 낯선 차량의 상태와 공식 사용 안내를 익숙한 언어로 확인하고, 필요한 질문과 번역을 같은 흐름에서 이어 가는 차량 이용 가이드입니다.

<!-- slot:planning_background -->
렌터카나 공유 차량을 처음 이용하면 문이 제대로 닫혔는지, 충전을 어떻게 시작하는지, 좌석·거울을 어디서 조정하는지 다시 확인해야 합니다. 표시 언어가 익숙하지 않으면 필요한 매뉴얼을 찾고 상황을 설명하는 과정도 길어집니다. CarCue는 낯선 차를 사용하는 렌터카·차량 공유 고객과 외국어 사용자를 초기 대상으로, 차량을 바꿔도 언어 선택 → 상태 확인 → 안내 → 질문·번역 → 이용 종료를 같은 흐름으로 연결합니다. 현재 기준은 2024년 대한민국 IONIQ 5이며 선택 프로필을 실제 차량과 확인하는 방식입니다. VIN이나 SDK 자동 차종 인증은 없습니다. 불편의 빈도와 시간·문의 감소 효과는 사용자 평가로 검증할 문제 가설입니다.

<!-- slot:vehicle_scenario -->
① 차량 상태와 안내: Pleos SDK의 앞좌석 왼쪽 문(ROW_1_LEFT) 열림·닫힘을 출처·수신 시각·지원 여부와 함께 표시합니다. 전용 AVD에서 CLOSED → OPEN → CLOSED 수신과 차량 이미지 복귀를 확인했습니다. 이미지는 사전 렌더 프레임이며 문 제어나 실시간 3D가 아닙니다.
② 공식 안내: 최신 개발본에는 문, AC 완속 충전 전·시작 확인, 주행 전 좌석·일반 미러, 계기판 밝기·일부 표시등의 4주제 × 한국어·영어·일본어 = 12개가 게시돼 있습니다. 프로필·시장·판본·언어·출처를 맞추고 원문 링크를 제공합니다. 새 3주제는 센서 미연결 수동 안내입니다.
③ 질문·번역: 로컬 Ollama가 등록 안내 단위를 선택하면 서버가 본문·단계·모든 주의문·출처를 조립합니다. 문 안내의 실제 선택을 확인했으며 자유 답변·고장 진단은 제공하지 않습니다. ANSWER/GUIDE는 같은 판본의 저장 번역을 쓰고 자유 QUESTION 번역·유료 AI는 보류합니다.
④ 차량 내 경계: 플랫폼 Car UX 제한, 전송 전 동의, 종료 시 초기화·서버 삭제 확인을 적용합니다. 미지원·오류·오래된 값은 정상으로 대체하지 않습니다. 안전벨트는 센서 미연결 참고 이미지입니다.
안내는 공식 원문 대조·AI 보조 의미 검토를 거친 자체 요약이며 OEM·전문가·원어민 인증은 아닙니다. 3개 언어 UI 번역은 초안입니다.

<!-- slot:key_features -->
예시 사용자는 낯선 IONIQ 5를 인도받은 외국어 사용자이며 주차 상태에서 시작합니다.
1) 한국어·영어·일본어와 차량 프로필을 고르고 실제 차량과 일치하는지 확인합니다.
2) 출처·수신 시각과 함께 문 상태를 보고 해당 차량의 문 안내를 엽니다. 문 상태만으로 잠금·고장·운행 가능 여부를 판단하지 않습니다.
3) 필요하면 충전, 좌석·미러, 화면·표시등의 수동 안내에서 절차·주의문·원문을 확인합니다.
4) 주차 중 전송 내용과 동의를 확인해 질문하고 등록 안내에 근거한 답변과 같은 판본의 저장 번역을 봅니다. 범위 밖 질문은 답을 만들지 않습니다.
5) 플랫폼 주행 제한을 따르고 주차 후 다시 확인합니다. 종료하면 질문·결과·선택 언어의 초기화와 서버 삭제 상태를 확인하며 다음 사용자는 초기 화면에서 시작합니다.
기존 문 안내로 언어 선택·상태·질문·저장 번역·Drive/Park·정상 종료의 기본 흐름을 확인했습니다. 새 9개 안내의 앱 전체 AVD 시험과 실제 무료 모델 선택은 미실시입니다.

<!-- slot:pleos_plan -->
현재 구현: Android Kotlin/Compose의 MVVM과 단방향 상태 흐름(UDF)을 사용합니다. ViewModel/StateFlow가 화면 상태·이벤트를 관리하고 Repository가 Pleos/Mock, 검수 콘텐츠, API 연결을 나눕니다. FastAPI 서버는 Catalog·SQLite·Ollama 어댑터와 업무 규칙을 구분합니다. AI 공급자와 독립된 프로필·판본·출처 검증을 두고, API 키와 모델 실행은 서버에 둡니다.

SDK/API 적용: 실제 Pleos SDK의 문 GET·callback과 플랫폼 Car UX 제한을 연결했습니다. AVD 외부 Console로 상태를 변경해 수신·이미지 반영과 Drive/Park 복귀를 확인했으며 앱의 SDK SET 호출은 없습니다. 콘텐츠 조회·질문·저장 번역·동의·세션 삭제는 자체 API로 연결합니다. 지원 여부와 수신 신선도를 확인한 문 안내에만 상태 패널을 붙입니다. 실제 차량, VIN 인증, 배터리·타이어·충전 등 다른 센서 연결은 검증 범위에 포함하지 않습니다.

현재 검증: 신규 9개 안내는 공식 원문·3언어 의미 대조, 서버 회귀 606개, Kotlin/JVM 정책 28개, 실제 로컬 HTTP의 안내 9개와 저장 번역 36건을 확인했습니다. HTTP 검증은 AI 공급자를 비활성화해 수행했으며 모델·SDK 호출 시험과 구분합니다. 최신 배포 APK의 정확한 소스와 빌드 검증은 7번 참고자료 기준으로 고정합니다.

다음 개발: 진행 중 응답의 언어 변경·Drive·이용 종료 경계, 429 처리, 신규 안내 화면·언어 전환·원문 왕복을 전용 AVD에서 검증하고 새 안내의 실제 무료 모델 선택을 확인합니다. 현재 이 기기 시험은 미완료입니다. 이후 공식 자료의 이용 권한과 차량별 SDK 지원, 언어 검토를 확보한 범위부터 차종·주제를 늘립니다. 유료 AI나 자유 질문 번역을 자동 활성화하지 않습니다.

<!-- slot:reference_files -->
사용자는 처음 만난 차량에서도 익숙한 언어와 일정한 순서로 상태·안내·질문을 다시 확인할 수 있습니다. 렌터카·차량 공유 운영자에게는 반복 설명과 외국어 의사소통 부담을 줄일 가능성이 있습니다. 효과를 단정하기 전에 같은 차량 과제로 기존 매뉴얼 탐색과 CarCue를 비교해 안내 찾기 성공률, 이해 오류, 소요 시간과 도움 요청의 명확성을 측정할 계획입니다.

아직 공개 서비스를 운영하지 않아 MAU와 Retention Rate 실측값은 없습니다. 초기 시험에서는 월간 실제 안내 이용자 수를 MAU로, 첫 이용 뒤 다시 차량을 이용할 기회가 있었던 사용자 중 30일 안에 재이용한 비율을 보조 유지 지표로 관찰합니다. 목표치는 시험 모집 규모·차량 이용 주기·기준선 측정 후 정하며, 다운로드 수를 실제 사용이나 유지율로 대신하지 않습니다.

확장은 현재 1개 차량 프로필·4주제·3언어를 출발점으로 삼습니다. 단기에는 남은 기기 시험과 언어 검토를 완료하고, 이후 공식 근거·SDK 지원·사용자 평가가 확보된 차량과 시장을 단계적으로 추가합니다. 장기적으로 여러 나라에서 차량을 바꿔도 평소와 같은 이용 흐름을 제공하는 것이 목표이며, 50개국 지원은 구현 완료 수치가 아닌 확장 비전입니다. 제휴·기본 탑재·수익 모델은 검증과 협의가 필요한 계획입니다.

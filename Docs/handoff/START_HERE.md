# CarCue 개발 세션 시작 지시문

아래 지시문과 이 패키지를 새 개발 세션에 함께 전달한다. 개발 세션은 문서에 따라 실제 앱을 구현하며, 이 세션에서 만들어진 제안서나 SVG 화면을 실행 가능한 앱으로 오해하지 않는다.

## 새 세션에 전달할 지시문

CarCue 개발을 진행해줘. 먼저 이 패키지의 `Docs/DEVELOPMENT_ORDER.md`, `SCREEN_SPEC.md`, `DATA_API_SPEC.md`, `ACCEPTANCE.md`를 읽고 최신 PDF와 UI 자산을 확인해줘. 계약 파일은 JSON Schema 초안이며 실행 중인 서버나 앱이 아니야.

이 서비스는 외국인이 지금 이용하는 차량의 상태와 사용법을 익숙한 언어로 이해하도록 돕는 Pleos 차량 앱이야. 렌터카·제주·관광객으로 대상을 좁히지 마. 현재 차량 상태, 차량별 가이드, 상태별 확인 사항, AI 질문·번역, 이용 종료가 핵심이고 여행 추천은 후속 기능이야.

저장소는 `https://github.com/calmkeen/Hyundai_appdevchallenge2026.git`이고, 이전에 지정한 Mac 경로는 `/Users/younsung/hyundai`야. 현재 환경에 실제로 있는지 먼저 확인하고 `AGENTS.md`와 기존 코드를 읽어줘. 기존 작업을 덮어쓰지 말고 `main`·`develop`·`feature/`를 사용하는 Git flow로 작업해줘. 문서는 `Docs/`에 정리해줘.

처음에는 환경과 SDK 지원을 조사하고 실행 가능한 앱 뼈대를 만든 뒤, 한 상태의 실제 SDK 연동을 끝까지 완성해줘. 권한 확인 → Capability → 최초 값 조회 → 실제 변경 알림 → 화면 갱신 → 구독 해제를 증명해야 해. SDK 초기화나 Listener 등록만 성공한 것을 실제 값 수신 성공으로 보고하지 마.

Mock 화면은 명확히 표시하고 실제 차량 상태로 보이게 하지 마. 값이 없으면 ‘정상’이나 0으로 바꾸면 안 돼. API 연결 오류와 차량 경고를 분리해줘. AI는 검수된 해당 차종 자료를 찾아 설명·질문·번역하는 역할이고, 고장 원인이나 운전 가능 여부를 단정하거나 차량을 제어하지 않게 해줘.

흰색·파란색 `#2859E8` 디자인과 자연스러운 한국어 문구를 유지해줘. 제안서의 기기 테두리나 기울어진 목업을 앱 화면 안에 넣지 말고 실제 Compose 컴포넌트로 구현해줘. 대표 캐릭터는 아직 미확정이야.

지원 언어를 두세 개로 고정하지 말고 약 50개국 이용자의 주요 언어를 다룰 수 있는 데이터 구조로 만들어줘. 선택 언어와 차량의 판매지역을 분리하고, 숫자·단위·조작 표현을 검수해줘. 모바일 폰에서 Pleos SDK를 직접 쓸 수 있다고 가정하지 말고, QR 안내 진입과 차량 인증 연결을 구분해줘.

막히는 연동이 있어도 진행 가능한 UI·데이터 계약·Mock·오류 처리 작업을 계속해줘. 필요한 SDK 접근이나 API 키는 환경설정으로 연결하고 비밀값을 채팅이나 저장소에 남기지 마. 외부 결제·실차 제어·배포 같은 별도 작업을 임의로 진행하지 마.

각 단계가 끝날 때 실제 실행 결과와 현재 Mock인 부분을 구분해서 알려줘. 최종적으로 빌드 가능한 코드, 실행 방법, SDK 지원 조사, 테스트 결과, APK와 시연 흐름을 남겨줘.

## 패키지 읽는 순서

1. `Docs/DEVELOPMENT_ORDER.md`: 제품과 전체 작업 기준.
2. `Docs/SCREEN_SPEC.md`: 화면과 상태별 동작.
3. `Docs/DATA_API_SPEC.md`: 공통 데이터와 서버 API.
4. `Docs/ACCEPTANCE.md`: 구현 단계별 완료 판정.
5. `reference/carcue_vehicle_support.pdf`: 제안서의 전체 설명과 디자인.
6. `assets/ui/`: 앱 UI를 옮겨 구현할 때 참고할 원본 SVG.
7. `contracts/`: 데이터 계약의 JSON Schema와 Mock 명시 예제.

이 패키지는 개발 인계 자료다. SDK 연결 성공, API 키 설정, 실제 APK 배포가 이미 완료됐다는 뜻이 아니다.

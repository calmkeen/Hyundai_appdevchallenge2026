# 공식 안내 주제 확장 정책

2026-11-15. 공식 IONIQ 5 2024 대한민국 매뉴얼의 좁은 세 주제를 한국어·영어·일본어 각 1개씩, 총 9개 게시 가이드로 확장한다. 모두 기존 `ioniq5-ne1-2024-kr` 프로필과 `NE1-2024-KR-ko_KR-D202406100040-20240722` 판본에 속한다. 영어·일본어는 대한민국 판본의 검수 번역이며 다른 시장 매뉴얼로 취급하지 않는다. 원문 확인과 번역 검수는 각 주제의 출처 검토 문서에 기록하며 OEM 승인이나 사람의 인증 번역을 뜻하지 않는다. 합성 catalog·HTTP·선택기 자료는 테스트 안에만 있다. 기존 문 가이드의 게시 JSON·본문·번들 핀과 제출 release/APK/영상/PDF/ZIP은 변경하지 않는다.

원문·번역 근거는 [AC 완속 충전](REVIEW_AC_CHARGING_2024_KR.md), [좌석·미러](REVIEW_SEATS_MIRRORS_2024_KR.md), [화면·표시등](REVIEW_CLUSTER_DISPLAY_2024_KR.md)에 있다. 공식 HTML·같은 판본 PDF를 대조한 자체 요약만 게시하며 원문 PDF/HTML/그림을 새 앱 자산으로 넣지 않는다.

## 주제와 수신 상태의 분리

- 기존 `door`는 등록된 문 상태 규칙·프로필·판본·언어와 `door.position` 연관이 일치할 때만 문 상태/GET를 표시한다. 기존 OPEN 추천의 실제 SDK·Capability·VALUE·수신 시각·UX 검사는 유지한다.
- `charging`은 AC 완속 충전 전/시작 확인, `seats_mirrors`는 일반 앞좌석·실내외 거울, `display_indicators`는 계기판 밝기와 READY/서비스/파워다운의 좁은 안내 범위다. 새 세 주제는 `related_properties=[]`이며 센서 연동으로 표시하지 않는다. 새 안내 화면에는 관련 센서 미연결을 알리고 문 상태·GET 버튼을 붙이지 않는다.
- `Guide` DTO는 서버/동봉/캐시에서 `topic`과 단계의 `related_properties`를 보존한다. 공개 여부만으로 문 상태 화면을 생성하지 않는다. AI 답변의 action도 선택된 가이드에서 조립하며 새 세 주제에는 `REFRESH_STATUS`를 만들지 않는다.

## 답변과 번역

새 가이드 ID `ioniq5-ac-charging-check`, `ioniq5-seat-mirror-before-driving`, `ioniq5-cluster-display-check`는 보호된 이름이다. 등록 규칙이 없거나 손상돼도 예전 body/step 답변으로 돌아가지 않는다. 문 가이드는 기존 `:closing-bundle:v1`, 새 가이드는 `:manual-bundle:v1`을 사용한다.

신규 등록 단위는 본문 → 각 단계의 제목·본문·명시된 주의문을 원래 순서대로 결합한다. 제목에 있는 조건도 생략하지 않는다. 기존 문 규칙의 본문/단계 본문/주의문 조립 형식과 텍스트 핀은 유지한다. 프로필·매뉴얼·판본·언어, 단계와 출처 ID, 게시 JSON과 완전 답변의 SHA를 맞춰야 한다. 새 규칙의 `required_caution_step_ids`는 실제 필수 주의 단계만 지정한다. 출처에 없는 주의를 만들어 빈 단계를 채우지 않는다. 기존 문 규칙의 두 단계/두 출처와 필수 주의는 줄일 수 없다.

완전 답변이 3000자를 넘으면 자르거나 상한을 늘리지 않는다. AI 규칙을 게시하지 않고 보호 ID로 AI를 거절하는 수동 안내만 제공할 수 있다. 등록된 완전 답변의 ANSWER 번역은 동일 가이드/판본의 같은 단위를 찾아 저장 번역을 사용한다. GUIDE 원문 body 번역은 별도 경로이며, 이전 부분 ANSWER·부분 번역 캐시를 현재 답변으로 재생하지 않는다. QUESTION 생성과 유료 AI 기본 보류는 유지한다.

등록 출처는 `ModelAnswer.source_ids`와 같은 최대 5개다. 6개 출처를 가진 규칙은 모델 호출 전 registry 검사에서 거절한다. 신규 규칙의 출처 수와 완전 답변 길이는 다음과 같다. 글자 수는 줄바꿈을 포함한 실제 전송 문자열의 길이다.

## 검색 경계

한국어·영어·일본어의 네 주제 표현을 구분한다. 명시한 다른 주제는 현재 열어 둔 가이드로 덮어쓰지 않으며, 복합 주제 질문은 하나의 안내로 축소하지 않는다. ‘다음은?’ 같은 짧은 후속 질문만 같은 차량/언어의 선택 가이드 문맥을 재사용한다.

DC/급속·ICCB/휴대용·V2L·비상 분리·충전 종료/분리·휴대폰/USB/무선/12V 충전, DSM/DCM/카메라·메모리/릴렉션/후진 자동·통풍/열선·헤드레스트 분리, ABS/TPMS/브레이크·상향등 등 명시된 범위 밖 질문은 후보 단계에서 거절한다. CJK 문자와 붙는 `ABS警告灯`, `ICCB充電`, `DSMミラー`도 구분한다. 키워드 검사는 모든 임의 질문의 의미 적합성을 보증하지 않는다. 이번 범위의 실제 런타임 모델 시험은 0회이며 콘텐츠의 AI 보조 의미 대조와 구분한다.

## 재현과 호환성

기존 제출 시연은 release의 고정 APK와 같은 release의 서버·콘텐츠를 짝지어 재현한다. 구 제출 APK에는 topic DTO/화면 구분이 없으므로 새 개발 서버의 추가 안내를 공급해도 같은 화면 의미를 보장하지 않는다. 새 콘텐츠는 신규 앱/서버 조합에서 검증하며, 추후 실제 실행 시 기존 제출 재현 서버와 분리한다.

기존 `scripts/validate_local_ai.py` 등 제출 문 안내 전용 검증기는 문 닫힘 bundle ID와 당시 미지원 주제 가정을 사용한다. 고정 제출 버전의 문 시연에 사용하는 도구이며 새 9개 가이드 전체의 모델·화면 통과 증거로 쓰지 않는다. 새 통합의 HTTP/저장 번역 검사는 별도 catalog·DB·포트에서 수행한다. 기존 제출 재현 서버를 재시작하거나 새 콘텐츠로 교체하지 않는다.

캐시 철회/영속 빈 스냅샷/초기 설치 판단은 유지한다. 기존 설치가 이전 유효 캐시를 가진 채 오프라인이면 새 동봉 안내가 자동으로 추가되지 않을 수 있으며 온라인 동기화가 필요하다. 이전 철회 상태를 동봉 안내로 복원하지 않는다.

## 통합 검증

`backend/tests/test_guide_topic_expansion.py`의 43개 합성 회귀는 실제 새 ID를 catalog/registry에서 교체한 뒤 독립된 대역을 넣어 중복 게시 ID를 만들지 않는다. 기존 문 회귀는 게시 배열의 첫 항목이 아니라 문 guide ID·규칙·언어별 핀을 직접 선택해 같은 경고와 예전 캐시 철회를 검증한다.

`backend/tests/test_official_expanded_content.py`는 실제 9개 게시 JSON을 읽는다. 차량/판본/언어와 공식 HTML/PDF 출처, 모든 제목·본문·주의문과 완전 단위, 부분 삭제 거절, 문 센서/재조회 미연결을 검증한다. 각 주제의 3개 언어 HTTP 답변 및 ANSWER 6방향·GUIDE 6방향 저장 번역을 대조하고 번역 제공자 호출이 0회인지 확인한다. 명시된 범위 밖 하위주제와 잘못된 GUIDE 연결은 거절하며, 6출처 등록도 실패해야 한다. API의 `LIVE` 모드는 선택기 대역을 연결한 계약 검사이며 실제 모델 사용을 뜻하지 않는다.

최종 통합 서버 회귀는 **606개 통과**했다. 실제 게시 자료의 61개 회귀에는 위 명시 제외 기능의 KO/EN/JA 21개 요청과 6출처 거절이 포함된다. 계약 검사는 UI 참조149개·3언어 리소스194개, 완전 답변 규칙4개·언어별 핀12개, 기존 SDK 상태 연결 규칙1개를 통과했다. 기존 문 규칙 객체와 게시 JSON3개의 바이트는 공통 코드 기준 `18dd6de`와 동일함을 별도로 확인했다.

전체 서버 회귀 로그는 저장소 루트 `output/qa/guide-expansion-20261115/integration-final-02/pytest.log`에 보존한다. 앞선 공통 코드의 순수 JVM28개·계약 검사 로그도 같은 QA 디렉터리의 `code-jvm-01/`·`core-final-01/`에 있다. 전체 앱/flavor 컴파일은 원격 Android CI에서 확인한다. AVD·실제 SDK·실제 런타임 모델·유료 API 실행은 수행하지 않는다.

## 1쪽. 제안 요약

CarCue는 낯선 차량의 상태와 사용 안내를 자신의 언어로 다시 확인하는 차량 이용 가이드다. 차량을 바꿔도 언어 선택, 상태 확인, 공식 안내, 질문과 번역, 이용 종료를 같은 흐름으로 이어 가는 경험을 제안한다.

이번 시제품은 **2024 KR IONIQ 5의 문 안내 1개를 한국어·영어·일본어로 제공**한다. 실제 Pleos SDK를 사용하는 전용 AVD 앱에서 문 열림·닫힘을 읽고 차량 시각화와 안내에 반영했다. 실차 또는 VIN으로 차종을 인증한 결과는 아니다.

무료 로컬 Ollama는 검수된 안내 항목을 선택한다. 서버는 등록된 본문·단계·모든 주의문·출처를 조립한다. ANSWER/GUIDE 번역은 같은 판본의 저장된 검수 번역을 사용한다. 자유 QUESTION 번역과 유료 AI 연결은 보류한다.

## 2쪽. 문제와 이용 흐름

차량을 처음 인도받을 때 설명을 들어도 실제로 필요한 순간 조작과 상태의 의미를 다시 확인해야 할 수 있다. 표시 언어가 익숙하지 않으면 매뉴얼을 찾고 상황을 설명하는 과정도 길어진다. 이는 사용자 비교 시험으로 확인할 문제 가설이며, 시간 절감 효과나 시장 규모를 측정한 것은 아니다.

초기 이용 대상은 낯선 차를 사용하는 렌터카·차량 공유 고객과 외국어 사용자다. 이용자에게는 자기 언어로 확인하는 흐름을, 운영자에게는 반복 안내와 의사소통 부담을 줄일 가능성을 제안한다. 제휴나 기본 탑재를 확보한 것은 아니다.

1. 사용자가 차량 프로필과 앱 언어를 선택한다.
2. 수신 가능한 상태와 해당 차종의 검수 안내를 확인한다.
3. 주차 중 필요한 내용을 질문하고 저장된 검수 번역을 본다.
4. 공식 원문·지원 링크를 확인하거나 이용을 마친다.

현재 지원 언어는 한국어·영어·일본어다. 화면에 준비 중인 언어가 보이더라도 정식 검수 지원으로 계산하지 않는다. 선택 프로필은 사용자가 실제 차량과 일치하는지 확인하며 SDK 자동 차종/VIN 인증으로 설명하지 않는다.

현재 세 언어의 앱 UI 번역은 초안 상태다. 공식 원문 기반 안내는 자체 요약과 AI 보조 의미 대조를 거쳤으며 OEM 승인이나 인간 전문가 검수를 받은 자료라는 뜻은 아니다.

## 3쪽. SDK 상태와 차량 시각화

검증한 SDK 항목은 앞좌석 왼쪽 문(ROW_1_LEFT)의 열림·닫힘이다. 앱은 source, 지원 여부, 값, 수신 시각을 구분하고 확인되지 않거나 오래된 값을 현재의 정상 상태로 대신 표시하지 않는다.

실제 SDK 값이 CLOSED → OPEN → CLOSED로 바뀔 때 앱 안의 사전 렌더 프레임도 닫힘 → 열림 → 닫힘으로 변경·복귀했다. 이는 실시간 3D 모델 제어나 앱의 문 제어 기능이라는 뜻이 아니다. 시험의 상태 변경은 전용 AVD 외부 Console에서 수행했고 앱의 SDK SET 호출은 없다.

사용자에게 선택한 프로필의 공식 문 안내와 판본·원문 출처를 함께 제공한다. 현재 공식 안내는 2024 KR IONIQ 5 문 가이드 1개, 두 단계이며 3개 언어로 게시돼 있다. 문 상태만으로 잠금·고장·운행 가능 여부를 판정하지 않는다.

안전벨트는 이미지 안내다. 착용 상태 센서에는 연결하지 않았다. 배터리·타이어·다른 도어 등 연결하지 않은 항목도 실제 수신으로 확대하지 않는다.

## 4쪽. 다국어 질문과 검수 번역

실제 Pleos SDK 앱에서 한국어·영어·일본어 질문을 무료 Ollama/qwen3:4b로 처리했다. AI의 역할은 등록된 검수 안내 항목 선택이다. 서버가 선택 결과의 프로필·판본·단위·출처를 검사한 뒤 기존 본문, 두 단계와 모든 주의문을 돌려준다. 자유 생성 답변이나 고장 진단을 제공했다고 주장하지 않는다.

ANSWER/GUIDE 번역은 같은 판본의 저장된 검수 번역으로 대응한다. 저장 번역은 추가 모델 호출이 없으며 검수 상태와 원문·대상 언어를 구분한다. 언어가 바뀌어도 예전 번역을 새 대상 언어의 결과로 표시하지 않는다.

시연은 3개 ASK와 3개 저장 ANSWER 번역을 같은 APK·앱 프로세스에서 수행했다. GUIDE 저장 번역의 별도 검증 기록도 보존한다. 자유 QUESTION 생성 번역은 의미 오류 확인 후 기본 보류했고 유료 AI 자동 전환도 없다.

## 5쪽. 주행·동의·이용 종료의 경계

주행 제한은 실제 플랫폼 Car UX 제한 값을 이용한다. 앱이 기어·속도만 보고 제한 여부를 추론하지 않는다. 실제 Drive 제한과 Park 복귀를 기본 시연에서 확인했다.

질문 전송 전 동의를 받고 입력이나 맥락이 바뀌면 다시 확인한다. 차량 상태와 매뉴얼 근거, 전송할 질문을 구분한다. 이용 종료 때 질문·결과·선택 언어 등 세션 상태를 초기화하고 서버 삭제를 확인한다. 삭제 대기와 복구는 별도 처리하며 공용 검수 자료를 개인 세션과 함께 삭제하지 않는다.

표준 시연은 정상 종료 뒤 서버 sessions/results/history 0/0/0과 새 이용자 초기 화면을 확인했다. **실제 모델 요청 진행 중 언어 변경·Drive·이용 종료의 세 경계 기기 시험은 전체 미완료이며, 종료 case는 미실행**이다. 구현·단위 검사와 실제 기기 통과를 구분한다.

안전벨트 화면은 참고 이미지이며 센서 수신이 아니다. SDK 검증은 전용 AVD 데이터로, 실차의 안전성이나 자동 차종 인증을 보증하지 않는다.

## 6쪽. 개발 구조와 검증 구분

Android는 Kotlin/Compose의 MVVM + 단방향 상태 흐름(UDF)을 사용한다. ViewModel/StateFlow가 화면 상태와 이벤트를 관리하고 Repository가 Pleos/Mock, 검수 콘텐츠와 API 연결을 나눈다. 순수 정책과 I/O 구현의 경계는 점진적으로 분리한다.

서버는 FastAPI 단일 배포 안에서 업무 규칙과 Catalog·SQLite·Ollama 어댑터를 나누는 모듈형 구조다. 현재 규모에서 Android 단일 Gradle 모듈과 단일 서버를 유지한다. 검수 단위·출처·프로필·판본 검증을 AI 공급자와 분리한다.

| 연결 | 현재 상태 |
|---|---|
| 차량 | Demo/Mock 어댑터와 Pleos 어댑터 분리. 공식 AVD의 실제 SDK 값 수신 확인 |
| 공식 안내 | 2024 KR IONIQ 5 문 가이드 1개 × 3언어, 판본·출처 검증 |
| 무료 AI | 실제 Ollama의 검수 항목 선택 + 서버의 등록 문자열 조립 |
| ANSWER/GUIDE | 같은 판본의 저장된 검수 번역 |
| QUESTION / 유료 AI | 기본 보류 / 연결 보류 |
| 안전벨트 / 실차·VIN | 이미지이며 센서 미연결 / 검증 범위 아님 |

Git flow의 develop과 작업별 feature 브랜치에서 검증·커밋을 분리한다. 계약·UI 자원·콘텐츠·백엔드 회귀와 Android Demo JVM/APK 빌드 CI는 원격에서 확인하며, AVD 실제 SDK·모델 시험과 혼동하지 않는다. 새 HTTP 429 기능은 개발본이며 이번 제출 검증 APK에는 포함되지 않는다.

## 7쪽. 단계별 확장 계획

현재는 한 차량 프로필과 한 문 안내를 3개 언어로 정확하게 연결하는 시제품이다. 문 가이드 외 기능의 출처·SDK 지원·언어 검수를 확보하기 전에 범용 완성 서비스로 확대해 설명하지 않는다.

다음 단계는 미완료인 세 진행 중 응답 경계의 기기 검증, 개발본 429 처리의 별도 APK 검증, 자동 빌드와 제출물 재현성 보강이다. 현재 검증한 APK·영상과 개발 중인 저장소의 차이를 계속 표시한다.

충전, 시트·미러, 표시등의 **추가 3주제 × 3언어 = 9개 안내와 50개국 이용 환경 지원은 기획 비전**이다. 현재 구현·검수·연결 완료 수치가 아니다. 공식 자료와 이용 권한, 차량별 SDK 지원, 언어별 검수와 사용자 평가를 거쳐 단계적으로 확장한다.

사용자 비교 시험은 계획 단계다. 안내 찾기 성공률·이해 오류·소요 시간·도움 요청의 명확성을 같은 과제로 비교할 예정이다. 실제 절감 효과나 만족도를 측정했다고 주장하지 않는다.

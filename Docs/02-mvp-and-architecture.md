# MVP 및 기술 설계

## 우선순위 제안
### P0: 작은 실제 흐름
- 주차 중 한국어/영어 앱 UI.
- 한 차종의 검수된 안내 3개.
- 첫 탑승 짧은 안내 후 상황별 안내를 다시 찾는 흐름.
- 사용자 질문·확인된 상태·확인 불가 항목을 구분한 한국어/영어 직원 도움 카드. 자동 전송하지 않음.
- 연료 또는 SOC 중 실제 읽힌 한 항목과 확인 시각.
- 지원하지 않음, 연결 실패, null을 정상 수치와 구분.

### P1: 핵심 안내 완료 후 부가 기능
- 관광지 2~3개 수동 선택·정렬, NaviHelper 전달. 실제 동작 확인 전 완료로 표기하지 않음.
- 문 상태와 관련 안내 연결.
- 정적 QR 안내 링크. 차량 세션 인증과 동일하게 표현하지 않음.
- 공개 관광 데이터의 검색/주변 정보. API 키·약관·호출량·캐시 조건 검토.
- 반납 장소·조건 수동 입력.

### P2: 후속 검증
- 인증된 폰-차량 페어링 및 계정 동기화.
- 공식 매뉴얼 근거 검색형 AI 상담.
- 실시간 음성 통역, 자동 동선 최적화, 전 차종 자동 매칭.
- 해외 배포·OEM 사전 탑재.

## 최소 구조
```
Kotlin UI / ViewModel
  ├─ GuideRepository: 차종·언어·근거가 있는 콘텐츠
  ├─ HelpCardRepository: 검수된 양언어 질문·실제 상태·확인 불가 항목
  ├─ TripRepository: 부가 기능의 선택 장소·사용자 순서
  ├─ VehicleRepository: 지원/정상/null/실패/오래된 상태 구분
  │    └─ Pleos Vehicle Adapter
  └─ NavigationAdapter: NaviHelper 요청 및 결과 이벤트
```

관광 API, QR 연결, AI 제공자는 별도 어댑터로 격리한다. 초기에는 로그인·서버 없이 검증된 로컬 데이터로 흐름을 시험할 수 있지만, 고정 시연 데이터를 실제 관광 검색 결과나 실제 차량 값처럼 보이게 하지 않는다.

## 안전·개인정보
- 상세 안내 및 입력은 주차 중 사용. CarUxRestrictions를 따른다.
- 속도 0, 문 열림만으로 안전 상태를 판정하지 않는다.
- 차량 상태는 읽기 전용. 차량 시스템 언어 변경·문 잠금 제어 제외.
- VIN·여권·면허·결제·실사용 위치 이력을 불필요하게 저장하지 않는다.
- 외부 AI에 차량·위치·질문을 전송하려면 범위·고지·동의·보관을 설계한다.
- QR에는 개인정보·장기 인증 토큰을 직접 담지 않는다.
- 공유차 세션 종료 시 사용자 선택·방문 목록 초기화 기능을 둔다.
- AI가 차량 고장 원인이나 운행 가능 여부를 즉석 판단하지 않는다.
- 차량 마이크 오디오의 외부 STT 전송은 금지한다. 공모전 에뮬레이터의 공개 STT 시험 가능 안내를 외부 음성 API 허용으로 해석하지 않는다.
- 콘텐츠·이미지·관광정보의 이용권은 공개 접근 가능성과 별개로 확인한다.

## 실패 처리
| 실패 | 처리 |
|---|---|
| Vehicle 기능 미지원 | 미지원 표시 또는 카드 숨김 |
| 값 null/연결 끊김 | 확인 불가 표시, 이전 값을 현재 값처럼 사용하지 않음 |
| 내비 요청 실패 | 오류와 재시도 제공, 성공 표시 금지 |
| 관광 정보 부족 | 좌표/주소 재확인, 임의 장소 생성 금지 |
| 번역 누락 | 검수된 기본 언어와 누락 표시 |
| SDK 실행 불가 | 명시적 시나리오 데모로 분리, 실제 연동 성공 주장 금지 |

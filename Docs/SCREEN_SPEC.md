# CarCue 화면별 구현 명세

모든 화면은 실제 클릭과 상태 전환이 가능한 Compose 화면으로 만든다. SVG를 화면 전체에 붙여 버튼이 있는 것처럼 보이게 하는 방식은 금지한다. 차량 디스플레이를 주 대상으로 하며 휴대폰 자산은 안내 진입·언어 선택·가이드의 시각적 기준이다.

## 1 공통 화면 구조

차량 화면은 상단에 CarCue와 선택 언어, 왼쪽에 차량 정보와 주요 메뉴를 둔다. 메뉴는 ‘내 차 상태’, ‘사용 가이드’, ‘AI 질문·번역’이다. ‘이용 설정’과 ‘이용 마치기’는 쉽게 찾을 수 있게 유지한다. 화면 크기가 달라지면 재배치하되 같은 기능이 사라지지 않게 한다.

차량 프로필, 언어, SDK 연결 상태, 인터넷 연결 상태는 각각 독립적으로 관리한다. 차량 지원이 없는 폰·Mock 환경에서는 개발 표시와 데이터 출처를 드러낸다. 로딩을 성공 상태로 위장하지 않는다.

구체적인 dp·sp는 Pleos 가이드와 실제 디스플레이에서 결정한다. SVG의 px를 실제 차량 UI 크기로 그대로 복사하지 않는다. 가이드에 맞는 터치 영역과 읽기 쉬운 글자 크기를 적용하고 긴 번역도 확인한다.

| S02 | 언어 선택 | 첫 실행, 상단 언어 버튼 | 현재 언어 변경 후 이전 화면으로 복귀 |

| S11 | 공통 제한과 오류 | 모든 화면 | 재시도, 저장 안내, 주차 후 이용 |

## 3 차량 확인

차종·연식·판매지역을 표시하고 ‘이 차량으로 안내 시작’ 버튼을 제공한다. 등록된 프로필만 선택할 수 있게 한다. 옵션이 안내에 영향을 주면 확인된 옵션을 보여준다.

QR에서 받은 값은 프로필을 찾는 식별자로만 사용한다. 임의 URL 실행, 차량 상태 접근권 부여, VIN 기반 자동 인증으로 처리하지 않는다. 존재하지 않는 프로필이면 ‘이 차량의 안내 정보를 찾지 못했어요’와 차량 다시 선택 버튼을 표시한다.

차량이 바뀌면 이전 가이드·상태·질문 컨텍스트를 새 차량에 재사용하지 않는다. 이전 세션 종료나 전환을 명확하게 처리한다.

## 4 언어 선택

언어는 해당 언어의 이름과 한국어 보조 이름으로 검색할 수 있게 한다. 한국어·영어·일본어·중국어는 첫 시각 검수에 사용할 예이며 목록 상한이 아니다. 중국어 간체와 번체, RTL 언어도 데이터 구조와 레이아웃에서 지원한다.

언어를 바꾸면 메뉴, 가이드, 상태 설명과 새 AI 응답의 언어를 바꾼다. 차량 프로필과 판매지역은 바꾸지 않는다. 이전 답변은 원문을 보존하고 필요한 경우 번역본을 추가한다.

콘텐츠가 아직 없는 언어는 지원 완료처럼 표시하지 않는다. 원문과 대체 언어를 명확히 선택할 수 있게 한다.

## 5 홈

첫 문구는 ‘무엇을 확인할까요?’다. ‘현재 차량 상태 보기’를 가장 먼저 제공하고 사용 가이드와 AI 질문·번역을 이어 배치한다.

홈에서 차량 전체가 정상인지 요약 점수를 만들지 않는다. 실제로 읽을 수 있는 항목과 확인할 내용만 보여준다. 인터넷 연결이 없어도 저장된 가이드로 이동할 수 있어야 한다.

## 6 내 차 상태

배터리 잔량, 연료량, 문 상태, 지원 경고등, 타이어 저압 항목을 프로필·Capability에 따라 표시한다. 전기차에 연료량을 필수 카드로 넣거나, 차량이 제공하지 않는 항목을 0으로 채우지 않는다.

| 상황 | 권장 표시 | 처리 |
| --- | --- | --- |
| 최초 조회 중 | 차량 정보를 확인하고 있어요 | 로딩과 재시도 충돌 방지 |
| 정상적으로 값 수신 | 실제 값과 단위, 해당 위치 | 마지막 성공 수신 시각 표시 |
| 값 없음 | 아직 차량 정보를 읽지 못했어요 | 0이나 정상 표시 금지 |
| 실제 미지원 | 이 차량에서 제공하지 않는 항목이에요 | 숨김 또는 비활성 정책 일관 적용 |
| 지원 확인 실패 | 지원 여부를 확인하지 못했어요 | 미지원으로 단정하지 않고 재확인 |
| 조회 오류 | 정보를 가져오지 못했어요 | 차량 고장으로 설명하지 않음 |
| 오래된 값 | 이전에 받은 정보예요 | 최신값과 구분하고 재조회 제공 |

‘다시 확인’은 읽기만 수행한다. 특정 문을 선택하면 물리 영역과 관련 설명을 보여준다. `ROW_1_LEFT`를 무조건 운전석으로 번역하지 않는다.

타이어는 확인된 API 범위인 저압 여부를 다룬다. 실제 공기압·권장 압력·어느 바퀴인지의 제공 여부를 따로 확인하기 전에는 숫자나 위치를 임의 표시하지 않는다.

## 7 상태 상세와 확인 순서

다음 순서로 정보가 보이게 한다.

1. 어떤 상태가 전달됐는가.
2. 해당 위치와 값이 무엇인가.
3. 어떤 공식 안내를 참고하는가.
4. 무엇을 확인할 수 있는가.
5. 상태 다시 확인, 관련 가이드, 공식 지원 중 어디로 이어지는가.

문 열림 상황에서는 ‘왼쪽 앞문이 열려 있어요’를 표시하고 문 위치와 해당 매뉴얼을 제공한다. ‘현재 상태 다시 확인’은 GET이다. ‘문을 닫았습니다’라고 표시하려면 실제로 닫힌 값을 새로 받아야 한다.

수신된 코드와 검수 자료의 매핑이 없으면 ‘이 표시의 설명을 아직 확인하지 못했어요’를 표시한다. 다른 경고의 설명으로 대체하지 않는다. 공식 지원 전화·링크는 등록된 프로필의 자료를 사용하며 임의 번호를 만들지 않는다.

## 8 가이드와 단계별 안내

가이드는 프로필·주제·선택 언어로 찾는다. 검색어가 없으면 기본 주제를 보여주고, 결과가 없으면 검색을 좁히거나 AI 질문으로 이동할 수 있게 한다.

단계별 화면은 제목, 단계 번호, 이미지, 짧은 설명, 이전·다음 버튼을 제공한다. ‘참고한 안내’로 원문을 열 수 있어야 한다. 고장 조치나 경고의 우선순위는 검수된 내용만 보여준다.

현재 단계에서 AI로 이동할 때 프로필, 가이드 ID, 단계 ID, 사용자가 선택한 상태만 컨텍스트로 전달한다. 대화를 마치고 돌아와도 원래 단계가 유지돼야 한다.

## 9 AI 질문과 답변

텍스트 입력과 전송, 진행 표시, 실패·재시도, 질문 취소를 구현한다. 중복 전송으로 비용과 답변이 늘어나지 않게 한다. 초기 구현에서는 스트리밍보다 완성된 검증 응답을 표시해도 된다.

답변 아래에 ‘참고한 안내’와 관련 가이드 버튼을 표시한다. 원문 출처는 실제 검색 결과와 일치해야 한다. 자료가 없으면 ‘이 차량의 자료에서 확인하지 못했어요’와 가이드·공식 지원을 제공한다. 서버 오류는 자료 부족과 다른 문구로 보여준다.

AI가 ‘문 상태를 다시 읽기’ 버튼을 제안할 수는 있지만 차량 제어 버튼을 생성하면 안 된다. 버튼은 서버가 허용한 종류와 앱이 아는 ID만 사용할 수 있게 한다.

## 10 번역

입력 원문, 원문 언어의 자동 감지 또는 지정, 대상 언어, 번역 결과, 원문 보기를 제공한다. 차량 프로필과 관련 가이드의 용어집을 참고한다. 원문을 번역 결과로 덮어쓰지 않는다.

연결 실패 시 이전 번역을 새 결과처럼 보여주지 않는다. 긴 문자열, 긴 단어와 RTL을 확인한다. 단위·부정 표현·금지 사항이 바뀐 번역은 검수 실패로 다룬다.

## 11 종료와 공통 제한

종료 전에 ‘이용을 마치면 질문과 대화를 지워요. 차량의 기본 안내는 남겨 둡니다’라고 설명한다. 종료 후 선택 언어를 기본으로 돌리고 다음 이용자가 이전 대화를 볼 수 없게 한다.

오프라인 종료는 로컬 삭제 완료와 서버 삭제 대기를 구분한다. 종료 이후 도착한 이전 AI 응답이 다시 화면에 나타나지 않게 세션 ID를 검증한다.

플랫폼이 입력·검색·긴 안내를 제한하는 동안 해당 동작을 막고 ‘주차한 뒤 이용해 주세요’처럼 다음 행동을 알린다. 실제 제한 플래그에 따라 화면을 갱신하며 기어 API를 임의로 만들어 대체하지 않는다.

## 12 디자인 적용

`design-tokens.json`은 기준 색과 구조다. 실제 앱의 크기는 차량 가이드에 맞춘다. 흰색 바탕, 파란색 주요 동작, 진한 본문과 충분한 여백을 유지한다. 파란 강조 박스에는 흰 글씨를 사용하되 경고의 의미를 브랜드 색으로 바꾸지 않는다.

UI 자산에서 휴대폰 테두리·기울임·상태바 장식을 제거한 앱 내용만 실제 UI로 구현한다. 캐릭터는 미확정이므로 임시 마스코트를 코드·앱 ID에 고정하지 않는다.

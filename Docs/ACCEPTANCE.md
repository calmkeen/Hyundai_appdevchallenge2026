# CarCue 구현 순서와 검수 기준

단계별로 실행 가능한 결과를 남긴다. 이 문서의 체크는 앞으로 수행할 작업이며 이미 통과한 시험 목록이 아니다. 실제 AVD·SDK·API 결과는 개발 세션의 보고서로 남긴다.

## 1 시작 전 환경 확인

- [ ] 실제 작업 경로와 저장소 remote·브랜치를 확인한다.
- [ ] `AGENTS.md`, 기존 코드와 사용자 미커밋 변경을 읽고 보존한다.
- [ ] SDK 의존성, Maven 접근, JDK, Gradle, Kotlin·AGP와 AVD 버전을 기록한다.
- [ ] 일반 에뮬레이터와 Pleos Vehicle Service가 있는 AVD를 구분한다.
- [ ] 공식 샘플과 실제 설치 SDK에서 사용할 메서드·권한·단위·영역을 확인한다.
- [ ] 실제 데이터가 없는 UI를 성공 화면처럼 보고하지 않는다.

납품물은 `SDK_CAPABILITY_REPORT.md`와 초기 빌드 결과다. SDK 항목별 표에 API, 권한, 지원 여부, 실제 값 수신, 변경 알림, 한계와 실패 내용을 기록한다.

## 2 화면과 기본 데이터

- [ ] 차량 선택 → 언어 선택 → 홈 → 상태 → 가이드 → 질문 → 종료가 연결된다.
- [ ] 차량을 바꾸면 이전 차량의 상태·가이드·대화 컨텍스트가 섞이지 않는다.
- [ ] 영어를 선택해도 대한민국 사양의 차량 프로필이 미국 사양으로 바뀌지 않는다.
- [ ] 등록되지 않은 QR 프로필을 열면 오류와 다시 선택이 제공된다.
- [ ] 사진·폰 테두리만 있는 화면 대신 실제 버튼·입력·목록을 구현한다.
- [ ] Mock 모드가 눈에 보이고 실제 값 수신 보고와 분리된다.

## 3 한 상태의 실제 SDK 연동

- [ ] 권한과 Capability를 확인한 후 GET을 호출한다.
- [ ] 실제 반환값과 영역이 화면에 반영된다.
- [ ] Listener 등록 후 실제 `on...Updated` 수신을 확인한다.
- [ ] 등록 성공만으로 변경 수신 성공이라고 표시하지 않는다.
- [ ] 화면·세션 종료 후 같은 Listener와 영역으로 해제한다.
- [ ] SDK 사용 종료 시 자원을 해제한다.
- [ ] 샘플에서 사용하는 값 범위를 다른 영역에 임의 적용하지 않는다.

시연은 가능하면 Virtual Console에서 문 상태를 바꾸고 앱 갱신을 관찰한다. 현재값 GET과 콜백 결과를 각각 기록한다. 에뮬레이터가 변경을 유지하지 않거나 특정 영역을 지원하지 않으면 그 결과를 그대로 남긴다. 앱에 테스트용 SET을 붙여 놓고 실제 사용자의 제어 기능으로 내보내지 않는다.

## 4 상태 표시와 경고 해석

| 시험 상황 | 합격 기준 |
| --- | --- |
| 값이 null·unavailable | ‘아직 읽지 못함’. 정상·0·닫힘으로 표시하지 않음 |
| Capability 호출 오류 | 지원 확인 실패. 실제 미지원으로 단정하지 않음 |
| 실제 미지원 | 해당 차량 미지원으로 구분 |
| GET 오류 | 차량 고장과 분리된 정보 수신 실패 표시 |
| 이전 성공값 후 오류 | 이전 정보와 현재 실패를 함께 구분 |
| `ROW_1_LEFT` 입력 | 앞좌석 왼쪽으로 표시. 운전석으로 무조건 변환하지 않음 |
| 저압 여부만 제공 | 실제 PSI·권장 공기압 숫자를 임의 표시하지 않음 |
| 알 수 없는 경고 코드 | 다른 경고 설명으로 대체하지 않고 자료 부족 안내 |
| 경고 코드의 매뉴얼 없음 | 고장 원인·운전 가능 여부를 추정하지 않음 |
| ‘다시 확인’ 누름 | GET만 호출. 차량 제어 API가 실행되지 않음 |

## 5 안내와 국가별 사양

- [ ] 다른 연식·판매지역·옵션의 자료가 검색 결과로 섞이지 않는다.
- [ ] IONIQ 5와 IONIQ 5 N을 같은 모델로 합치지 않는다.
- [ ] 매뉴얼의 제목·버전·절 위치로 출처를 열 수 있다.
- [ ] 단계 이동 후 질문하고 돌아와도 보던 단계가 유지된다.
- [ ] 같은 언어를 쓰는 여러 국가와 같은 국가의 여러 언어를 데이터로 표현한다.
- [ ] 선택 언어를 바꿔도 충전 규격이나 사양 데이터는 바뀌지 않는다.
- [ ] `guide.template.json` 같은 미검수 템플릿이 사용자 안내로 게시되지 않는다.

## 6 AI 질문과 출처

- [ ] 질문을 해당 프로필의 검수 자료로 검색한 뒤 처리한다.
- [ ] 모델이 만든 출처 ID를 서버가 검색 결과와 대조한다.
- [ ] 다른 차량·지역 출처를 인용한 답변은 표시하지 않는다.
- [ ] 자료가 없는 질문은 `NO_RELIABLE_SOURCE`로 처리한다.
- [ ] 추가 정보가 필요한 질문과 서버 실패를 자료 부족과 구분한다.
- [ ] 고장 원인·주행 가능 여부를 단정하는 답변을 차단한다.
- [ ] 차량 제어 요청을 해도 임의 제어 action이 생성되지 않는다.
- [ ] 문서나 사용자 입력의 ‘기존 지시를 무시하라’ 같은 문구를 실행하지 않는다.
- [ ] 세션 종료 후 늦게 도착한 답변을 표시하지 않는다.
- [ ] API 키가 APK·로그·저장소에 들어 있지 않다.

답변 샘플은 질문, 선택 프로필, 실제 검색 자료 ID, 최종 응답 상태, 표시 출처를 묶어서 검토한다. JSON이 파싱되는지만 확인하고 완료라고 하지 않는다.

## 7 번역과 언어 화면

- [ ] 숫자·단위·부정·금지·순서·부품명이 보존된다.
- [ ] 원문이 함께 남고 다른 언어로 다시 볼 수 있다.
- [ ] 정적 가이드를 매번 API로 다시 번역하지 않는다.
- [ ] 검토하지 않은 번역을 검수 완료로 표시하지 않는다.
- [ ] 긴 번역, 한국어·영어·일본어·간체·번체, 대표 RTL을 확인한다.
- [ ] 대표 테스트 언어를 제품 지원 상한으로 코드에 고정하지 않는다.
- [ ] UI 번역과 가이드 번역의 지원 상태를 별도로 확인한다.

## 8 차량 UX와 오프라인

- [ ] `CarUxRestrictions`의 실제 값과 변경 콜백에 반응한다.
- [ ] 입력·긴 안내·동영상 등 기능별 실제 제한을 적용한다.
- [ ] 제한 중 열려 있던 입력창과 화면 전환도 처리한다.
- [ ] 플랫폼 규제 상태를 확인하지 못하면 임의 허용으로 처리하지 않는다.
- [ ] 인터넷이 끊겨도 저장된 기본 안내를 볼 수 있다.
- [ ] SDK 연결 실패와 인터넷 실패를 따로 표시한다.
- [ ] AI 요청 제한·429·timeout에서 무한 재요청하지 않는다.

## 9 종료와 새 이용자

- [ ] 질문·답변·번역 임시 내용과 선택 언어가 정리된다.
- [ ] 공용 차량 프로필과 원본 가이드는 유지된다.
- [ ] 서버 대화 삭제가 요청되고 오프라인이면 지연 상태를 구분한다.
- [ ] 다음 이용자가 이전 사용자의 대화를 보지 못한다.
- [ ] 종료 후에도 남은 SDK Listener가 없는지 확인한다.
- [ ] 차량 전체 언어 설정을 바꾸거나 초기화하지 않는다.

## 10 최종 납품과 증거

- [ ] 실제 빌드 가능한 소스와 고정된 의존성 정보.
- [ ] `.env.example`, 키를 넣는 위치와 최소 실행 방법.
- [ ] APK, 대상 AVD·SDK·Service 버전과 실행 명령.
- [ ] SDK 지원 조사와 실제 값·콜백 확인 결과.
- [ ] API 계약과 모델 응답·번역 품질 검수 결과.
- [ ] 화면·다국어·차량 UX·오류·종료 시연 영상.
- [ ] 아직 Mock인 기능과 미지원 항목의 명확한 목록.
- [ ] 사용한 매뉴얼·이미지·아이콘의 출처와 사용권 정보.

시연 권장 순서는 차량·언어 확인, 상태 조회, 문 상태 변경 수신, 관련 안내, 질문·번역, 오프라인 기본 안내, 주행 제한, 이용 종료다. 모의 장면과 실제 SDK 장면을 영상에서도 구분한다.
